# CallPilot

A Claude Code skill that automatically processes meeting transcripts after client calls and routes each item to the right place — no servers, no infrastructure.

After every client or stakeholder call, CallPilot:
- Extracts every actionable item (bugs, enhancement requests, new feature asks)
- Routes each to the right engineering team using your config
- Takes action automatically

| Item Type | Complexity | Action |
|-----------|------------|--------|
| Bug | Simple | Draft PR opened in your repo |
| Bug | Complex | Slack ping to team oncall with full context |
| Feature enhancement | Simple | Draft PR opened in your repo |
| Feature enhancement | Complex | Slack ping to team oncall |
| New feature | Any | Backlog issue filed |
| Ambiguous routing | Any | Posted to your fallback channel |

## Setup (5 minutes)

**1. Copy and fill in the config:**
```bash
curl -o callpilot.yaml \
  https://raw.githubusercontent.com/Manpreet-2002/callpilot/main/examples/callpilot.example.yaml
```
Edit `callpilot.yaml` — add your teams, repos, and Slack channels. The `description` field on each team is the most important: the more specific it is, the better CallPilot routes.

**2. Set your transcript API key:**
```bash
# Fireflies (most common)
export FIREFLIES_API_KEY=your_key_here

# Or Otter
export OTTER_CLIENT_ID=your_client_id
export OTTER_CLIENT_SECRET=your_client_secret

# Or Zoom
export ZOOM_ACCOUNT_ID=your_account_id
export ZOOM_CLIENT_ID=your_client_id
export ZOOM_CLIENT_SECRET=your_client_secret
```

**3. Make sure GitHub and Slack MCP are connected in Claude Code:**
```
/mcp
```
You need both `github` and `slack` servers connected. CallPilot uses their tools directly — no separate auth needed.

**4. Create the `callpilot` label in your repos:**
```bash
gh label create callpilot --color 0075ca --description "Auto-generated by CallPilot" --repo your-org/your-repo
```

**5. Schedule it:**
```
/schedule callpilot every 30 minutes
```

That's it. After every call, transcripts are processed and your team gets actionable work items — automatically.

## How It Works

```
Your meeting ends
      ↓
Fireflies/Otter/Zoom creates transcript
      ↓
CallPilot wakes up (on schedule)
      ↓
Polls transcript API for new meetings since last run
      ↓
Extracts all actionable items using Claude
      ↓
Routes each item to the right team via callpilot.yaml
      ↓
  ┌───────────────────────────────┐
  │  Simple bug/enhancement       │→ Draft PR opened in repo
  │  Complex bug/enhancement      │→ Slack ping to team oncall
  │  New feature                  │→ GitHub Issue in backlog
  │  Ambiguous routing            │→ Posted to fallback channel
  └───────────────────────────────┘
      ↓
Saves state (won't reprocess same meeting)
```

## Supported Transcript Sources

| Source | `type` value | Required env vars |
|--------|-------------|-------------------|
| [Fireflies](https://fireflies.ai) | `fireflies` | `FIREFLIES_API_KEY` |
| [Otter](https://otter.ai) | `otter` | `OTTER_CLIENT_ID`, `OTTER_CLIENT_SECRET` |
| [Zoom](https://zoom.us) | `zoom` | `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` |
| Manual paste | `manual` | none — drop `callpilot_transcript.txt` in project root |

## Configuration Reference

Full annotated example: [`examples/callpilot.example.yaml`](examples/callpilot.example.yaml)

| Field | Description | Default |
|-------|-------------|---------|
| `transcript_source.type` | Your transcript tool | required |
| `teams[].name` | Team identifier | required |
| `teams[].description` | Natural language description of what this team owns. Richer = better routing. | required |
| `teams[].repos` | GitHub repos this team owns (used for reading code and opening PRs) | required |
| `teams[].slack_channel` | Slack channel to ping for complex items | required |
| `teams[].oncall` | Slack handle to mention | required |
| `backlog_repo` | GitHub repo where new feature issues are filed | required |
| `fallback.strategy` | What to do when routing is ambiguous: `slack_channel`, `github_issue`, or `ping_both` | `slack_channel` |
| `fallback.slack_channel` | Channel for ambiguous items | required |
| `fallback.mention` | Slack handle to mention in fallback | required |
| `routing.confidence_threshold` | 0.0–1.0. Below this → fallback. Lower = more aggressive routing. | `0.75` |
| `pr.draft` | Always open PRs as drafts (strongly recommended) | `true` |
| `pr.label` | GitHub label on all CallPilot PRs | `callpilot` |

## Multi-Team Routing

CallPilot supports any number of teams. Each team's `description` is matched semantically against the extracted item. The more specific your descriptions, the better it routes.

When an item spans multiple teams (e.g. "the auth data doesn't show correctly on the dashboard"), CallPilot either picks the best match above the confidence threshold or falls back to your `fallback.strategy` if it can't decide.

---

## State

CallPilot tracks processed meetings in `callpilot.state.json` in your project root. This file is auto-managed — don't edit it manually. Each meeting is only processed once.

## Running Once (Without a Schedule)

You can always trigger CallPilot manually:
```
/callpilot
```
